Anthropic 平台负责人揭秘：Claude Managed Agents 的设计哲学与一年后的形态
Anthropic Claude 平台产品负责人 Angela 和工程负责人 Caitlin 分享了为什么要打造 Managed Agents，以及下一步往哪走。

核心洞见：大多数开发者以为最难的是"harness engineering"（如何搭好对话框架、配好工具），但实际上，大家真正踩坑的是把 agent 推上生产——服务器保活、sandbox 崩溃、转写数据存哪。这就是 Managed Agents 存在的原因。内部实践案例：Anthropic 自己用 Managed Agents 构建了法务审核 agent，让市场人员直接把文案丢进去，agent 先过滤一遍，只有有争议的才转到法务人工审核。

对于"模型锁定"的担忧，Angela 给出了一个清醒判断：通用 harness + 热插拔模型的时代正在过去，harness 和模型会越来越深度耦合，真正的差异化来自把两者调到最优。

关于一年后的形态，她的愿景是：Claude 自己会理解自己，自动决定用哪个模型、启动多少 sub-agent、选哪种架构——用户只需要给出"outcome + budget"两个参数。

"你不再需要做 harness engineering，因为 Claude 足够了解自己，能在运行时把自己写出来。"

📝 Anthropic Engineering
Managed Agents：把大脑和双手分开
Anthropic 工程博客发布了关于 Managed Agents 架构演进的深度文章。核心洞见：把 Claude 的"大脑"（harness）与"双手"（sandbox/tools）以及"记忆"（session log）彻底解耦，各自成为独立接口，互相可以故障、替换而不影响对方。

效果显著：解耦后 p50 首 token 延迟下降约 60%，p95 下降超 90%。安全边界也更清晰——未受信任的代码跑在 sandbox 里，OAuth token 存在 vault 外，harness 对凭证完全不知情。

类比操作系统：就像 read() 命令在 1970 年代磁盘和现代 SSD 上都能跑，Managed Agents 的接口设计是为"尚未被设计出来的 harness"而生的。

📝 Anthropic Engineering
Claude Code auto mode：一种更安全的跳过权限审批方式
Anthropic 发布 Claude Code 的 auto mode，填补了"每次手动审批"和 --dangerously-skip-permissions 全量放行之间的空白。核心是两层防御：输入层用 prompt injection（提示注入）探针扫描工具输出，发现疑似劫持内容时向 agent 发出警告；输出层则用基于 Sonnet 4.6 的 transcript classifier 进行二阶段分类——第一阶段快速单 token 过滤（宁可误拦，不漏危险），第二阶段仅对被拦截的 action 进行 chain-of-thought 推理以降低误报。

实测数据：在 1 万条真实内部流量中，误报率（FPR）从 stage 1 的 8.5% 降至完整 pipeline 的 0.4%；对 52 条真实"过度主动"行为的漏报率（FNR）为 17%。Anthropic 坦承：auto mode 面向的是因审批疲劳而已经无脑放行的用户，而非认真手动审批每个 action 的用户的替代品。
